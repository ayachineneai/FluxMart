# 支付

## 范围

第一阶段只实现支付宝电脑网站支付：

- 一个订单对应一个支付单。
- 支付单创建后，可以在支付截止时间前重复获取支付页面。
- 支付金额始终取订单应付金额，客户端不提交金额。
- 支付结果以支付宝异步通知或主动查询为准，不以浏览器同步跳转为准。
- 暂不实现多支付渠道、拆分支付、部分支付和退款。

## 参与方

- 用户浏览器：发起支付并跳转支付宝收银台。
- 订单模块：持有订单金额、支付期限和订单状态。
- 支付模块：持有支付单，调用支付宝并处理支付结果。
- 支付宝：受理支付、返回支付页面、发送异步通知并提供交易查询与关闭接口。
- 库存模块：支付成功后确认库存预占；订单关闭后释放库存预占。

## 整体流程

```text
用户选择支付
│
├── 创建或取得支付单
│   ├── 校验订单属于当前用户
│   ├── 校验订单为 PENDING_PAYMENT
│   ├── 校验订单尚未超过支付期限
│   └── 使用订单金额创建支付单
│
├── 调用 alipay.trade.page.pay
│   └── 返回支付宝支付表单
│
├── 浏览器跳转支付宝并完成支付
│
├── 支付宝异步通知支付结果
│   ├── 验签并核对通知身份
│   ├── 核对支付单、订单和金额
│   └── 在同一事务中完成支付成功
│       ├── 支付单改为 SUCCEEDED
│       ├── 订单改为 PAID
│       └── 库存预占改为 CONFIRMED
│
└── 浏览器同步返回结果页
    └── 前端查询本系统订单状态并展示结果
```

## 发起支付

输入只需要订单业务编号，不接受客户端传入支付金额。

```text
pay(orderCode, currentUserId)
├── 查询订单
├── 校验订单归属、状态和支付期限
├── 按 orderId 查询支付单
│   ├── 不存在：生成 paymentId、paymentCode 并创建 PENDING 支付单
│   └── 已存在：复用原支付单
├── 以 paymentCode 作为支付宝 out_trade_no
├── 以订单 totalAmount 作为支付宝 total_amount
└── 返回支付宝支付表单
```

支付单必须先成功持久化，再向客户端返回支付表单。重复发起同一订单的支付时复用同一个 `paymentCode`，不重复创建本地支付单。

## 同步返回

浏览器从支付宝跳回系统，只代表用户完成了支付宝页面流程，不代表支付一定成功。

同步返回页不修改支付单、订单或库存，只根据 `orderCode` 查询本系统订单状态：

- `PAID`：展示支付成功。
- `PENDING_PAYMENT`：展示处理中，并允许前端短暂轮询。
- `CLOSED` 或 `CANCELLED`：展示订单已关闭或取消。

## 异步通知

异步通知是支付成功的主要入口。

```text
notify(parameters)
├── 使用支付宝公钥验签
├── 校验 app_id、seller_id
├── 根据 out_trade_no 查询 payment
├── 查询 payment 对应的 order
├── 校验 total_amount 等于订单金额
├── 判断 trade_status 为支付成功状态
└── 事务内幂等处理支付成功
```

只有验签、通知身份、支付单和金额全部核对通过后，才能修改本地状态。事务提交成功后向支付宝返回 `success`；处理失败时不能返回 `success`，由支付宝重试通知。

支付宝可能重复发送同一通知，因此支付成功处理必须幂等：

- 支付单已经是 `SUCCEEDED` 时直接视为成功。
- 只有 `PENDING -> SUCCEEDED` 可以首次触发订单支付成功和库存确认。
- 同一支付单不能重复确认库存。

## 主动查询

异步通知可能因网络或服务故障未到达，因此系统必须能够调用 `alipay.trade.query` 主动查询。

主动查询用于：

- 用户从支付宝返回后，订单仍处于待支付状态。
- 支付宝异步通知长时间未到达。
- 关闭超时支付前确认支付宝侧最终状态。
- 定时任务对长期处于 `PENDING` 的支付单进行补偿。

查询结果为支付成功时，复用与异步通知相同的支付成功处理，不建立第二套状态修改逻辑。

## 超时关闭

订单到达 `paymentExpiresAt` 后不能直接在本地关闭，必须先确认支付宝侧是否已经支付：

```text
closeExpiredPayment(orderId)
├── 查询支付宝交易状态
├── 已支付
│   └── 执行统一的支付成功处理
└── 未支付
    ├── 调用 alipay.trade.close
    └── 事务内完成本地关闭
        ├── 支付单改为 CLOSED
        ├── 订单改为 CLOSED
        └── 库存预占改为 RELEASED
```

主动查询与关闭支付宝交易用于处理“支付成功”和“超时关闭”并发发生的边界。只有确认支付宝交易未支付并成功关闭后，才能关闭本地订单并释放库存。

## 状态

### 支付单状态

```text
PENDING ──支付成功──> SUCCEEDED
   │
   └──交易关闭──> CLOSED
```

- `PENDING`：支付单已创建，尚未确认支付成功或关闭。
- `SUCCEEDED`：支付宝确认支付成功，终态。
- `CLOSED`：支付宝交易和本地支付单均已关闭，终态。

支付失败不单独作为终态。用户取消付款、关闭收银台或暂时支付失败后，在支付期限内仍可使用同一个支付单重新支付。

### 与订单状态的关系

| 支付单状态 | 订单状态 | 库存预占状态 |
| --- | --- | --- |
| `PENDING` | `PENDING_PAYMENT` | `RESERVED` |
| `SUCCEEDED` | `PAID` | `CONFIRMED` |
| `CLOSED` | `CLOSED` | `RELEASED` |

订单主动取消时，也需要关闭仍为 `PENDING` 的支付宝交易，然后将支付单置为 `CLOSED` 并释放库存。

## 核心规则

- 支付单金额来自订单，不信任客户端金额。
- 一个订单只创建一个支付单，一个支付单只属于一个订单。
- `paymentCode` 全局唯一，并作为支付宝 `out_trade_no`。
- 只有待支付且未过期的订单可以发起支付。
- 支付成功以验签后的异步通知或主动查询结果为准。
- 同步返回不能修改支付状态。
- 支付成功、订单已支付和库存确认必须在同一事务中完成。
- 支付成功处理必须幂等。
- 本地关闭订单前必须确认并关闭支付宝交易。
- 支付相关私钥只能保存在服务端，不能写入代码或返回客户端。

## 支付单数据

### `payment`

| 字段 | 定义 |
| --- | --- |
| `id` | UUIDv7 数据库内部主键 |
| `payment_code` | 系统生成的支付单业务编号，同时作为支付宝 `out_trade_no` |
| `order_id` | 所属订单内部主键，一对一且唯一 |
| `channel` | 支付渠道，当前固定为 `ALIPAY` |
| `status` | `PENDING`、`SUCCEEDED` 或 `CLOSED` |
| `amount` | 从订单复制的支付金额，单位为人民币分 |
| `provider_trade_no` | 支付宝生成的交易编号，支付成功后写入 |
| `paid_at` | 支付成功时间 |
| `closed_at` | 支付关闭时间 |
| `version` | 乐观锁版本，用于处理支付成功与关闭并发 |
| `created_at` | 创建时间 |
| `updated_at` | 最后修改时间 |

支付截止时间只保存在订单的 `payment_expires_at`，支付单不重复保存。

## 实现顺序

1. 实现创建或取得支付单。
2. 封装支付宝支付页面、查询和关闭能力。
3. 实现异步通知验签与支付成功事务。
4. 实现同步返回后的本地状态查询。
5. 实现订单超时关闭与主动查单补偿。
6. 使用支付宝沙箱完成端到端测试。

## 当前边界

仓库目前已定义订单、订单项、库存预占和支付单表，但尚无订单及支付应用代码。支付模块的实现依赖订单创建流程先能够产生 `PENDING_PAYMENT` 订单及 `RESERVED` 库存预占。
