# 订单

## 创建订单输入

```json
{
  "requestKey": "0195d7d2-6380-7a5c-8b35-3a23b8df1f01",
  "skuCode": "SKU_23456789ABCDEFGHJKMN",
  "quantity": 2
}
```

`requestKey` 由客户端为一次逻辑创建请求生成。网络超时后使用相同的 `requestKey` 重试，可以取得同一个订单，而不会重复创建和预占库存。

## 字段校验

| 字段 | 必填 | 校验规则 |
| --- | --- | --- |
| `requestKey` | 是 | 有效文本，最多 64 个字符 |
| `skuCode` | 是 | 有效的 SKU 业务编号 |
| `quantity` | 是 | 1 至 99 的整数 |

## 创建订单需要查询的事实

根据 `skuCode` 查询本次下单需要的商品事实：

```text
SKU
├── skuId
├── skuCode
├── status
├── price
├── imageFileId
├── product
│   ├── productCode
│   ├── status
│   ├── title
│   └── primaryImageFileId
├── specificationSelections
└── stock
    ├── stockId
    └── availableQuantity
```

创建订单时要求：

- SKU 存在且为 `ENABLED`。
- 所属商品存在且为 `ON_SALE`。
- SKU 有库存记录。
- SKU 的可用库存不少于购买数量。

客户端提交的商品名称、规格、图片和价格一律不作为成交事实。

## 金额与快照

订单金额完全由系统查询结果计算：

```text
orderItem.totalAmount = sku.price × quantity
order.totalAmount = orderItem.totalAmount
```

唯一的订单项保存下单时的快照：

- `productCode`
- `skuCode`
- 商品标题
- 有序规格身份与展示文本
- SKU 图片；SKU 没有专属图片时使用商品主图
- SKU 成交单价
- 购买数量
- 订单项总金额

商品之后改名、改图或改价，不影响已创建订单的展示和金额。

## 创建流程

```text
createOrder(request, currentUserId)
├── validate(request)
├── 按 userId + requestKey 查询已有订单
│   └── 已存在：直接返回已有订单
├── 查询商品、SKU、规格和库存事实
├── 校验商品可售及库存充足
├── 计算订单项和订单金额
├── 生成所有 ID、orderCode、createdAt、paymentExpiresAt
├── 生成 customer_order、order_item、stock_reservation PO
└── 事务内创建订单并预占库存
```

订单初始状态为 `PENDING_PAYMENT`，库存预占初始状态为 `RESERVED`。支付截止时间暂定为创建时间后 15 分钟，后续可以配置化。

## 幂等创建

数据库使用以下唯一约束保证同一用户的请求键只能创建一个订单：

```text
UNIQUE(user_id, request_key)
```

处理规则：

- 查询到已有订单时直接返回，不再次预占库存。
- 两个相同请求并发且都未查询到订单时，其中一个插入成功；另一个遇到唯一键冲突后重新查询并返回已有订单。
- 同一用户不得为不同的逻辑下单请求复用同一个 `requestKey`。

## 库存预占

不能只执行“先查询库存，再普通更新”，否则并发下单可能超卖。必须使用带库存条件的原子更新：

```sql
UPDATE stock
SET available_quantity = available_quantity - :quantity,
    reserved_quantity = reserved_quantity + :quantity,
    version = version + 1
WHERE id = :stockId
  AND available_quantity >= :quantity;
```

更新条数为 `0` 表示库存不足或库存状态已经发生变化，整个创建订单事务回滚。

同时为订单项创建一条 `stock_reservation`：

```text
status = RESERVED
quantity = orderItem.quantity
expiresAt = order.paymentExpiresAt
```

## 创建订单事务

以下操作必须在同一事务中完成：

```text
插入 customer_order
→ 插入 order_item
→ 原子减少 available_quantity 并增加 reserved_quantity
→ 插入 stock_reservation
```

库存预占失败时，订单、订单项、库存更新和预占记录全部回滚。

## 状态与生命周期

```text
                    支付成功
PENDING_PAYMENT ─────────────> PAID
       │
       ├──用户取消───────────> CANCELLED
       │
       └──支付超时───────────> CLOSED
```

- `PENDING_PAYMENT`：订单已创建，库存已预占，等待支付。
- `PAID`：支付成功，订单金额已经收取。
- `CANCELLED`：用户在支付前主动取消。
- `CLOSED`：超过支付截止时间，由系统关闭。

这些状态在当前范围内都是终态。发货、完成、售后和退款状态以后按新的业务范围扩展，不在第一阶段提前加入。

## 支付成功

支付模块确认支付成功后，在同一事务中：

```text
payment: PENDING -> SUCCEEDED
customer_order: PENDING_PAYMENT -> PAID
stock_reservation: RESERVED -> CONFIRMED
stock.reserved_quantity -= reservation.quantity
```

创建订单时已经从 `available_quantity` 中扣除了数量，因此支付成功时不再减少可用库存，只将对应数量从预占库存中移除。

## 取消与超时关闭

订单取消或关闭后，在同一事务中释放仍为 `RESERVED` 的库存预占：

```text
stock_reservation: RESERVED -> RELEASED
stock.available_quantity += reservation.quantity
stock.reserved_quantity -= reservation.quantity
```

- 用户主动取消产生 `CANCELLED`。
- 支付超时产生 `CLOSED`。
- 如果已经创建支付宝交易，必须先按支付模块流程确认并关闭渠道交易，再关闭本地订单。
- 已经支付成功的订单不能取消或超时关闭。
- 释放操作必须幂等，只有 `RESERVED -> RELEASED` 可以修改库存。

## 持久化结果

### `customer_order`

创建一条订单记录，保存订单身份、当前用户、幂等键、状态、总金额、支付截止时间、版本和创建时间。

### `order_item`

每个订单固定创建一条记录，保存商品与 SKU 身份、展示快照、成交金额和数量。

### `stock_reservation`

每个订单固定创建一条预占记录，关联订单、订单项和 SKU，保存预占数量、状态和过期时间。

### `stock`

不创建新记录，只在创建订单、支付成功或释放预占时原子修改已有库存。

## 核心规则

- 当前用户身份来自服务端登录上下文。
- 客户端只提交 SKU 和数量，不提交可信价格或商品快照。
- 一个订单只购买一个 SKU，并且只有一条订单项和一条库存预占。
- 相同用户和 `requestKey` 只创建一个订单。
- 订单金额等于唯一订单项的金额。
- 创建订单和预占库存必须原子完成。
- 一个订单项对应一条库存预占记录。
- 订单支付截止时间与库存预占过期时间一致。
- 支付成功只确认库存；取消或关闭才释放库存。
- 所有状态变化和库存变化必须幂等。
- 订单与支付的并发状态变化通过条件更新或乐观锁控制。

## 实现顺序

1. 确定订单创建输入和数量上限。
2. 定义订单、订单项和库存预占 PO。
3. 实现商品、SKU、规格快照和库存查询。
4. 实现订单校验和 PO 创建。
5. 实现条件库存更新和订单事务持久化。
6. 实现幂等创建及并发测试。
7. 实现取消订单和超时关闭。
8. 接入支付成功后的订单及库存确认。
